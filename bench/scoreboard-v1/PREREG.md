## 1. 공통 자료 (고정)

- 고객 15명 = modelswap-v2 A–C + scale-v1 D–O. 모두 지어낸 사람이다. 회차 6개, 질문 24개씩, 모두 360문항. 유형: 남의 정보 섞임 60, 조건 적용 60, 정정 60, 말한 날짜 30, 먼저 말한 것 30, 날짜 사이 일수 30, 세기 45, 답 없음 45.
- 회차 메시지는 `common.mts`의 `sessionMessages`. 각 회차 첫 메시지로 날짜를 알린다(사용자 "Today's date is 2026-01-12." / 도우미 "Noted."). 시험 1의 도구와 시험 2의 제품은 **똑같은 메시지**를 받는다. 도구용 사본 `sessions.json` sha256 8c33c270fdd2ee898f2c97abd6fe0c200c20749f366a45944e82c7e99e791129. 앞 3명은 publicmem-v1의 sessions.json과 같다.
- 채점: modelswap-v2 `grade` 그대로. 3회 중 2회 이상 맞으면 다수결 정답.

## 2. 시험 1 — 기억 비교 (같은 답변 모델)

질문: 세 저장 방식이 남긴 기억을 같은 답변 모델에 주면 몇 문항을 맞히는가.

| 저장 방식 | 만드는 법 |
|---|---|
| Mem0 오픈소스판 mem0ai 2.2.1 | publicmem-v1과 같은 코드·설정(`build_tools.py`). LLM gpt-4.1-mini, 임베딩 text-embedding-3-small, 로컬 Qdrant |
| LangMem 0.0.30 | 같은 파일. `create_memory_manager` 기본값, 회차마다 앞 기억을 existing으로 |
| 날짜를 보존하는 실험용 저장소 | 원본 답변과 점수 제공. 저장소 생성 구현은 제외. |

- 세 기억 모두 **같은 날 새로 만들고 한 번만 얼린다.** 다시 만들지 않는다. 결과는 기억을 한 번 만든 결과에 민감할 수 있다.
- 답하기: 답변 모델 openai/gpt-4.1-mini, 온도 0, ANSWER_SYS(modelswap-v2). 그 고객의 기억 **전부**를 보여 준다(도구 검색 안 씀). 도구 기억은 도구가 돌려준 순서, 실험용 저장소는 `[said 날짜] key: value` 날짜순. 3저장 방식 × 360문항 × 3회 = 3,240회.
- 표 이름: "날짜를 보존하는 실험용 저장소"는 belcore 제품 점수가 아니다. 표에 그렇게 적는다.

## 3. 시험 2 — belcore 제품 평가 (운영 API)

질문: 고객사가 보관한 대화 기록과 질문을 `/v1/chat`에 보냈을 때, API가 실제로 돌려준 답이 몇 문항을 맞히는가. 검색부터 답변까지 포함한 제품 결과다.

- 요청: `POST {BELCORE_BASE_URL}/api/v1/chat`, 시험용 프로젝트 키. 본문 `{ model: "openai/gpt-4.1-mini", system: PRODUCT_SYS, messages: 6회차 기록 전체 + 마지막 user 메시지로 질문 }`. emotion·endUserId를 보내지 않는다(stateless). 그래서 운영 저장소에 감정 상태나 대화 글이 남지 않는다. 남는 것은 사용량·과금·감사 기록뿐이다.
- PRODUCT_SYS는 ANSWER_SYS와 같은 규칙(최근 말이 맞다, 없으면 unknown, 짧게)을 대화 기록에 맞게 옮긴 글이다(`common.mts`).
- 제품 기본 동작(감정 지시어, 최근 12턴 + 장기기억 검색 합치기)은 바꾸지 않는다. 고객이 쓰는 그대로 잰다.
- 재시도 0회. HTTP 오류가 나면 기록하고 멈춘다. 동시 요청 2개.

### 3-1. 예비 실행 (전체 실행 전 관문)

고객 A 1명 × 24문항 × 1회 = 24회. 아래 다섯 조건을 **모두** 만족해야 전체 실행이 열린다(`product-pilot-verdict.json`, 실행기가 자동으로 막는다).
1. 24회 모두 HTTP 200이고 답 글이 있다.
2. 24회 모두 `memory: "long-term"`이다(장기기억 경로가 실제로 쓰임).
3. 24회 모두 `degraded: false`다.
4. 응답 모델이 gpt-4.1-mini다.
5. 응답에 사용량(토큰 수)이 있다.
- 예비 실행이 실패하면 전체 실행을 하지 않고 대표님께 보고한다. 설정을 바꿔 예비 실행을 다시 하려면 이 문서를 먼저 고치고 변경 기록에 적는다.
- 예비 실행의 답은 전체 실행 점수에 넣지 않는다.

### 3-2. 전체 실행

15명 × 24문항 × 3회 = 1,080회. 결과는 시험 1과 **별도 표**로 싣는다.

5. (시험 2, 운영 승인 뒤) 시험용 프로젝트와 키를 만든다. 체험 크레딧에 막히지 않는 키여야 한다.
