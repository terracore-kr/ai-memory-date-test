## 2. 실행 순서 (Codex, 맥)

1. 운영 배포 원본(현재 dpl_Gq7LKPWehwoiT76AtdZepssFYNjx의 소스)에 패치를 적용한다. 바뀌는 파일은 app/api/v1/chat/route.ts와 새 파일 2개뿐이어야 한다. 단위 시험 → 미리보기 배포 → 운영 배포.
2. 시각 없는 기존 요청이 그대로 동작하는지 확인한다(배포 후 일반 호출 1회, 응답 모양 동일).
3. 새 시험용 키. `npx tsx bench/scoreboard-v1/ts1/run.mts pilot` — 먼저 잘못된 timestamp 요청 세 가지("not-a-date", "2026-01-12T99:99:99Z", null)가 400인지 확인(기능 배포 확인, 모델 호출 없음)한 뒤 고객 A 24문항 1회. 여섯 조건 통과 시에만 full이 열린다.
4. `npx tsx bench/scoreboard-v1/ts1/run.mts full` → `ts1/score.mts > ts1/RESULT.txt`
5. 시험 키 폐기. 키 값은 출력하지 않는다. 멈추면 다시 돌리지 말고 그대로 보고한다.
- 서버 오류(5xx)는 fix2와 같이 기록하고 오답으로 세며 계속한다. 6개 이상이면 멈춘다.

## 3. 표기

공개한다면 제품 표에 "시각 없이 보낸 경우"와 "메시지 시각을 함께 보낸 경우"를 별도 줄로 적는다. 시험 1(저장 방식 비교)과는 계속 별도 표다. 시각을 다루는 내부 방법은 쓰지 않는다.
